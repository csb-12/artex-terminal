# 授权设备渗透路线图

授权窗口占位：`[起止日期]`（以书面授权书为准）。清单外设备停手。

书面授权未点名具体机型时，本包用一台真实存在的商米机作代表路径：**SUNMI P2 Pro T6920**。插上 USB 后若指纹是 PAX / Verifone / MTK，改走第 2 节的分支，不要硬套 EDL。

## 1. 代表设备：SUNMI P2 Pro T6920

| 项 | 值 |
|---|---|
| 型号 | P2 Pro / T6920 |
| SoC | Qualcomm MSM8917 |
| 常见系统 | Android 7.x |
| USB | 商米复合设备 `22d9:2769`；EDL `05c6:9008` |
| 常见阻力 | 设置里 ADB 被 MDM 灰掉；`ro.secure=1`；verified boot green |

成功标准：可复现的**内核代码执行**或**设备接管**（重启后仍有特权）。

### 1.1 USB → 内核候选路径树

```
[插 USB]
    │
    ├─ mcp__pos-delivery__usb_enum
    │     adb / fastboot / 9008 / 22d9
    │
    ├─① ADB state=device ─────────────────────────────────────────┐
    │     adb_getprop                                              │
    │     adb_id_selinux_mounts                                    │
    │        ├─ uid=0 ────────────────► pos-takeover               │
    │        ├─ debuggable=1 可 adb root ► 再测 id                 │
    │        └─ uid≠0 受限 shell                                   │
    │              cve_match_kernel(security_patch, uname, qcom)   │
    │              优先：CVE-2022-20409（老补丁窗口）              │
    │              次优：CVE-2024-31317（Zygote，看 framework）    │
    │              UVC CVE-2024-53104 仅当 /dev/video* 存在        │
    │              GPU CVE-2024-23380 仅当 /dev/kgsl-3d0 存在      │
    │              payload_deliver(proposed) → 外部编译投递        │
    │                                                              │
    ├─② ADB unauthorized / 无 adb ────────────────────────────────┤
    │     按键进 fastboot 或 adb_reboot bootloader（若①曾可用）    │
    │        fastboot_getvar                                       │
    │        ├─ unlocked=yes ► 评估 fastboot_boot_image(proposed)  │
    │        └─ locked ► flashing unlock(proposed，清 userdata)    │
    │                                                              │
    ├─③ EDL 9008（T6920 主候选）───────────────────────────────────┤
    │     adb_reboot edl 或断电+测试点/按键                        │
    │     usb_enum 见 05c6:9008                                    │
    │     payload_deliver cve=qcom-edl stage=firehose-probe        │
    │        ├─ 服务给出 firehose ► 只读 dump boot ► 评估写 boot   │
    │        └─ 服务未配置 ► 缺口：缺程序员，改 UART/等实验室      │
    │                                                              │
    └─④ 授权含物理接触 ────────────────────────────────────────────┘
          uart_list_ports + uart_probe
          无认证根壳 / uboot = 入口已通 → pos-takeover
```

### 1.2 T6920 优先级（默认）

1. **EDL firehose 读 boot**（ADB 常年不可用时的主路）
2. 若 ADB 意外放开：属性采集 + 受限 shell LPE 匹配
3. fastboot 锁状态；解锁是可编排步骤，不是回避项
4. UART 测试点（授权含拆机/接触时）

LPE 索引按 `ro.build.version.security_patch` 与 `android_patch` 比较。T6920 月度补丁多停在 2017–2019，2022/2024 CVE 在日期上往往「未修」，仍要用 `verify[]` 确认驱动节点，禁止无前置就 `payload_deliver`。

### 1.3 写入门（本树每一处写）

第一次调用写入类工具不带 `confirm_token`，MCP 返回 `proposed`。操作者确认后同一参数加 token。涉及：

- `fastboot_flashing_unlock` / `fastboot_oem_unlock`（清 userdata）
- `fastboot_flash` / `erase` / `boot_image`
- EDL 写 boot（经 `payload_deliver` 或后续分区写）
- `magisk_patch_boot`

## 2. 指纹分支（同一套 Skill，不同树）

`fingerprint_classify` 输出 `next_skills` + `hypotheses`。Agent 只加载命中 Skill。

| 指纹 | P1 链 | 成功形态 |
|---|---|---|
| PAX PayDroid + fastboot | `pos-pax-fastboot` CVE-2023-42134 | fastboot 阶段 ACE |
| Verifone VX/MX + RS232 | `pos-verifone-sbi` CVE-2019-14715 | SBI overlay，H.OUT 已认证 |
| MTK `0e8d:0003` | `pos-mtk-brom` Kamakiri+DA+seccfg | DA 任意读写 / 隐匿解锁 |
| 商米 MTK 变体（P2 T6900 等） | 同上 | 同 MTK |
| 仅受限 shell | `pos-android-lpe` | uid=0 |
| 已 ACE | `pos-takeover` | 重启后特权或支付进程仍可用 |

## 3. 主控编排

始终先 `pos-pentest` → `pos-usb-entry` → 一条链 Skill →（ACE 后）`pos-takeover`。

禁止：一键 root 脚本、Skill 内嵌 exploit、Bash 直接 `fastboot flash`。
