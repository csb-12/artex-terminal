# 安卓 / OS 代码审计

思路来自 [从一千多个「漏洞」到三处没修完的补丁](https://xz.aliyun.com/news/93403)（Treasure Map）：

- 工具**不跑模型、不判漏洞**。给每个函数打「漏洞」标签会得到一千个误报。
- 每条候选六层：来源 / 可控 / 写入者 / 可达 / 过滤 / 分析完整。取值只有是、否、**未知**（未知写原因）。
- **未知不等于安全**，不能靠分数把未知沉底。
- 事实层只读，标注层可写，判断必须引用 `evidence_ref`。
- 补丁对比问三件事：是不是安全修复、修完整了吗、别处还有没有。没修完的典型形态：入口断了处理函数还在；缓冲区变大拷贝长度没变；校验只加在前端。
- 没读过标未读，不标没问题。

## 本包怎么落地

原生 Windows 跑不了 Ghidra/BinDiff（Treasure Map 官方也这么写）。所以 `mcp__pos-delivery__audit_*` 在宿主机提供**可跑的事实地图**：

| 面 | 扫什么 |
|---|---|
| 安卓 | APK 清单 exported / debuggable、DEX 字符串（Runtime.exec、loadLibrary、WebView JS）、JNI `.so` |
| OS | ELF 危险导入（system/popen/strcpy/sprintf/open）、init.rc service、脚本 system/eval/chmod 777 |

函数级伪代码对比：WSL2 安装 [Treasure Map](https://github.com/JoeyZzZzZz/treasure-map)，本工具会在 `tmap` 字段里标明缺口，不假装已经反编译。

聊天页选 **终端渗透**，加载 `pos-code-audit`：

```text
授权 POS。这是已解包的 system dump：/path/to/t6920-fs
按事实地图审计安卓 APK 和 native，不要把扫描命中当漏洞。
有旧版本 /path/to/t6920-fs-old 就对比修没修完。
```

或设备已 adb：

```text
设备已授权且 adb device。拉厂商 APK 画地图，exported 和 Runtime.exec 只记事实。
```

## 工具顺序

1. `audit_scan` 或 `audit_collect`
2. `audit_list`（可按六层重排，候选集合不变）
3. `audit_get` → 读伪代码/清单/导入（本层没有 Ghidra 伪代码就读文件与字符串）
4. `audit_annotate` 写判断
5. 两个 dump：`audit_diff`
6. 收尾看 `audit_coverage`

禁止用一千条 DEX 命中交差。代码审计进度 ≠ 内核 ACE。
